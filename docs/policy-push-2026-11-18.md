# 关注新文件微信提醒

已复用现有微信 AppID / AppSecret，并通过微信官方 API 添加和核验“政策更新通知”模板。原有“每日推壁纸更新通知”模板保留，政策功能不使用该模板。平台返回的新模板为一次性订阅（type 2），不能把用户关注当作永久推送许可。

## 用户流程

1. 在“关注”页添加地区、主题规则（可包含国家级文件）。
2. 点击“开启微信提醒”，在微信原生弹窗同意订阅；每次同意对应一条汇总通知。再次点击可补充次数。
3. 后台按北京时间每日 09:00 汇总本次订阅后新收录、符合关注规则的文件，无更新不发送。仅对收录当日最近 7 天发布的文件提醒，避免历史补采触发大量旧文通知。
4. 点击微信服务通知进入“关注更新”页，再进入文件详情。测试版授权跳转体验版，开发版授权跳转开发版，正式版授权跳转正式版。
5. 用户可暂停提醒或取消关注；发送前再次检查当前关注规则。

历史已收录文件、缓存导入、同一文件的内容修订不触发“新文件”提醒。每人每天至多一条正常汇总，同一文件不会因多个关注规则重复推送。09:00 后补到的待发送事件可在当天补发；服务恢复时最多补收最近 7 天的未提醒文件。

## 实现与故障处理

- API：`GET /api/v2/me/push`、`POST /me/push/prepare`、`POST /me/push/confirm`、`DELETE /me/push`、`GET /me/updates/{digest_id}`。全部需要本账号登录；跨账号授权和更新记录不可访问。
- 原生授权调用直接由按钮点击触发，之前不会等待网络登录。授权结果在本机短暂保存，服务端确认失败可重试同一 grant，不会重复增加次数。
- 新增 4 张表存储订阅、授权凭据、每日发送记录与文件清单；现有数据不重建、不回填通知。新文写入既有 outbox，已有 worker 内启动独立通知线程，无需第四个服务。
- 发送前原子领取任务、预留一次额度。明确未发送的连接错误、令牌过期等最多尝试 3 次，最终失败退还本地额度；微信拒绝订阅则停止提醒。
- 请求超时、未知响应、发送中进程退出等无法确认送达的情况记为 `uncertain`，不自动重发，也不退还可能已消耗的额度。运维需核查后处理，不能直接把此状态批量改回 queued。
- `sent` 代表微信接口返回成功；手机实际展示仍需真实用户验收。本地测试使用模拟授权和发送，未给真实用户发送通知。
- 不记录 AppSecret、微信 token、openid 或完整微信错误响应。
- 回归中修复采集线程同时保存相同原文哈希时的唯一键冲突，避免无必要地推迟新文件采集。

## 上线

`deploy/enable-policy-push.py --revision <完整提交SHA> --source-sha256 <本地指纹>`：

1. 使用既有 `sync-release.py` 下载并校验完整固定版本，备份数据库和服务定义，切换三个现有服务。
2. 使用服务器原有 `ai.env` 中的 AppID / AppSecret，只读确认模板属于当前小程序、名称及字段准确（`thing5 / number12 / date7 / thing4`）。
3. 备份私有配置，原子写入 `POLICY_WECHAT_PUSH_TEMPLATE_ID` 和 `POLICY_WECHAT_PUSH_ENABLED=true`，保留其他配置和密钥，权限 0600。
4. 重启 API 和采集 worker，检查三服务 active，以及 `/health` 的版本、源码指纹、`wechat_push_available=true`。激活失败则还原私有配置并重启。

新页面及授权按钮需要重新上传小程序代码，不能只替换服务器。先同步服务器，再使用包含 `pages/updates/updates` 的新测试版完成真实授权和送达验收。不要求重新填写 AppSecret。

暂停全站通知：在服务器私有 `ai.env` 设置 `POLICY_WECHAT_PUSH_ENABLED=false` 并重启 `nhc-api`、`weijianwei-worker`。请勿在公开仓库保存该文件。
